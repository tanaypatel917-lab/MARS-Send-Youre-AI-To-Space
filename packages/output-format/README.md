# @mars/output-format

`@mars/output-format` parses, validates, serializes and renders the MARS Output Format: the structured model-to-UI contract whose AST lives in `@mars/contracts` (`OutputDocument`, writing blocks, follow-ups, links, app triggers, review links, typed `OutputError`s). The format is specified in [documentation/OUTPUT_FORMAT.md](../../documentation/OUTPUT_FORMAT.md); that spec lands in the same output-format parent PR as this package, so the link resolves once both are merged.

Everything parsed here is untrusted model text. `parseOutput` never throws on model output; every problem becomes a typed error and the offending lines stay Markdown. `validateOutput` checks a document against host facts (`connector_ids`, `allowed_addresses`, `max_review_lines`); `processOutput` runs both and returns `{ document, errors, ok }`. `serializeOutput` is the inverse of the parser and `rewriteWritingBlocks` lets a host replace or redact blocks before display. `followUps` and `writingBlocks` are segment selectors, and `OUTPUT_FORMAT_PROMPT` is the system-prompt fragment that teaches a model the format.

## Terminal renderer

`renderTerminal(document, { width?, errors?, color? })` is a pure function returning a string for terminals: Markdown segments are printed as-is, each writing block is a box-drawn frame with a header (variant, id and, for email, subject, to, cc, bcc) and one labelled section per tone, follow-ups are collected into a numbered "Follow-ups" chooser that shows each hidden prompt, app triggers and review links are listed under "Proposed actions (not executed)" with the connector id or PR, path and line range, and validation errors appear under "Format errors" with line numbers. Width defaults to 80 (headers truncate, bodies wrap, the frame never breaks); output is deterministic and contains no ANSI codes unless `color: true`. Pass `errors` from `processOutput` so context errors are listed and rejected proposals are marked.

The renderer never executes anything. `bun apps/cli/src/main.ts render [file] [--connectors id1,id2] [--address a@b.com]... [--follow-up N] [--json]` wraps it: `--json` prints the processed document, `--follow-up N` prints only that follow-up's hidden prompt so a shell can pipe it into a steer command after the user has read it, and format errors are reported without changing the exit code (exit 1 is reserved for I/O and argument errors).
