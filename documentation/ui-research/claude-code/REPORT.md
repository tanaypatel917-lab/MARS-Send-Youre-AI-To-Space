## 1. Permission model

**Modes** `[ran]` `claude --help` lists `--permission-mode <mode>` with choices `acceptEdits, auto, bypassPermissions, manual, dontAsk, plan`, plus `--dangerously-skip-permissions` and `--allow-dangerously-skip-permissions`. `[docs permission-modes]` `default` is the config-file name for what the UI calls "Manual": reads are auto-approved, everything else prompts. `acceptEdits` also auto-approves file edits and common FS commands (`mkdir touch mv cp rm rmdir sed`) inside working dirs, subject to protected-path rules. `plan` = read/explore only until the plan is approved. `auto` = each tool call is screened by a background classifier for risk/prompt-injection; low-risk runs, rest blocked; now the default. `dontAsk` = reads + pre-approved tools, anything that would prompt is denied. `bypassPermissions` = no prompts; intended for isolated containers/VMs; a confirmation dialog precedes it unless `skipDangerousModePermissionPrompt`.

**First-run notice** `[ran]` On the first REPL start a left-barred notice reads: "Auto mode is now Claude Code's default permission mode. Auto mode lets Claude handle permission prompts automatically. Claude checks each tool call for risky actions and prompt injection before executing, runs the ones it assesses as lower-risk, and blocks the rest." + docs URL (screenshot 02).

**Mode indicator and cycling** `[ran]` The mode is the first item of the single footer line under the prompt box. Observed strings: `⏵⏵ auto mode on (shift+tab to cycle)`, `⏸ manual mode on · ? for shortcuts`, `⏵⏵ accept edits on (shift+tab to cycle)`, `⏸ plan mode on (shift+tab to cycle)`. Observed cycle from a session that started in auto: auto → manual → accept edits → plan → manual → … (auto did not reappear in this API-key session). `[docs permission-modes]` "From `auto`, the first press switches to `default`, and the cycle then runs `default` → `acceptEdits` → `plan`. Optional modes slot in after plan": auto when available, bypass when enabled; `dontAsk` is never in the cycle. Glyph grammar: `⏸` for modes that will stop and ask (manual, plan), `⏵⏵` for modes that proceed (accept edits, auto, don't ask, bypass). In `xterm` with DejaVu Sans Mono the `⏸/⏵⏵` glyphs did not render, so the footer showed only the words (screenshots 10, 12–18) — a font-fallback risk to design for.

**Permission prompt** `[docs permissions]` (not observed live; official screenshot `images/permission-prompt-bash-light.png` on the page, alt text quoted): a panel titled by tool kind ("Bash command"), a one-line tip about auto mode, the model's description ("Run the test suite"), the command (`npm test`), the line "This command requires approval", the question "Do you want to proceed?" and the options:
1. `Yes`
2. `Yes, and don't ask again for: npm test *`
3. `Yes, and switch to auto mode` (only in Manual/acceptEdits when auto is available)
4. `No`
Footer: `Esc to cancel · Tab to amend` (Tab lets you attach a comment to the answer; `[docs interactive-mode]` "Tab … add a comment to a permission answer"). `Esc` declines. Some prompts offer only a one-time approval when the rule they would save cannot be shown in full. Reads outside working dirs have their own three options: `Yes, and keep allowing any reads outside the working directories` / `No, and block reads outside the working directories from now on` / `No, and ask again next time`. Edits to `.claude/` get `Yes, and allow Claude to edit files in this project's .claude folder for this session`. The exact "No, and tell Claude what to do differently" wording from the task brief is **not verified** in 2.1.317 docs; the current wording is `No` + `Tab to amend`.

**Rules** `[docs permissions]` "don't ask again" writes a rule to `.claude/settings.local.json` at the git root, in the space-wildcard form `Bash(npm test *)` (`:*` suffix is the equivalent trailing form). Compound commands save one rule per sub-command. File-edit approvals last only for the session. Rule kinds: `allow`, `ask`, `deny`; deny wins over everything including bypass mode. Rule syntax `Tool`, `Tool(specifier)`, e.g. `Read(./.env)`, `WebFetch(domain:example.com)`, `mcp__server__tool`.

**`/permissions`** `[ran]` Opens a tabbed panel: `Permissions · Recently blocked · Allow · Ask · Deny · Auto mode · Workspace`; tab copy "Claude Code won't ask before using allowed tools."; a `⌕ Search…` box; row `1. Add a new rule…`; footer `←/→ to switch · ↓ to select · Esc to cancel` (screenshot 07).

## 2. Plan mode

`[docs permission-modes]` Enter with `Shift+Tab` (twice from manual), `/plan [description]`, or `claude --permission-mode plan`. Claude can read, search, fetch and write a plan file but cannot edit source or run mutating commands. Status bar `⏸ plan mode on` `[ran]`. When the plan is ready Claude presents it and asks; options: **`Yes, and use auto mode`** (reads `Yes, auto-accept edits` where auto is unavailable), **`Yes, manually approve edits`**, **`No, keep planning`**. `Ctrl+G` opens the plan in `$EDITOR` to edit before continuing. `showClearContextOnPlanAccept` adds a "clear context" option at the accept screen. `/config` has `Use auto mode during plan` (true) `[ran]`. The plan is re-injected after compaction `[docs context-window]`. Spinner tip text promotes it: "Use Plan Mode to prepare for a complex request before making changes. Press Shift+Tab twice to enable." `[docs settings-reference]`. Live plan-approval UI: not observed (needs a model reply).

## 3. Slash commands

**Autocomplete** `[ran]` Typing `/` opens a list of 5 rows directly above the prompt box, two columns (name, then dim description), `❯` on the selected row; typing filters; `Tab`/`Enter` accept; `Esc` closes. First rows: `/add-dir  Add a new working directory`, `/advisor  Let Claude consult a stronger model at key moments`, `/auto-mode-setup  Teach auto mode about your environment, plus optional rule tweaks`, `/autocompact  Set how full the context gets before auto-summarizing`, `/background  Send this session to the background and free the terminal` (screenshot 03). Executed commands echo into the transcript as an inverse-video pill `❯ /model` followed by an indented result line (`Kept model as Opus 5.5 (default)`, `Resume cancelled`, `Help dialog dismissed`).

**`/help`** `[ran]` Tabbed dialog `Help · General · Commands · Custom commands`. General = one-line blurb + the 3-column shortcut sheet (see §7). Commands tab "Browse default commands" showed 6 rows + `↓ 80 more` ⇒ 86 built-ins exposed to this account.

**Custom commands / skills** `[docs skills]` The unit is a *skill*: `<dir>/<skill-name>/SKILL.md` with YAML frontmatter + Markdown body; invoked as `/<skill-name> [args]` or by the model when `description` matches. Locations: enterprise managed dir, `~/.claude/skills/`, `.claude/skills/` (project), plugins; legacy `.claude/commands/*.md` still load as skills `[docs skills]` (section "commands directory", not re-verified live). Frontmatter keys: `name`, `description`, `argument-hint`, `arguments`/`$ARGUMENTS`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks`, `paths`. `/reload-skills` rescans; `/skills` lists; `/skill-doctor` shows per-skill context cost. Skill descriptions are truncated in the model's listing (`skillListingMaxDescChars`).

## 4. Context management

`[ran]` `/context` prints into the transcript (no API call): title `Context Usage`, a row of coloured glyphs (one glyph per ~10% bucket, coloured by category), then a right column `Opus 5.5 / claude-opus-5-5 / 34.9k/1m tokens (3%)`, *Estimated usage by category*: `System prompt: 2.7k tokens (0.3%)`, `System tools: 29.9k tokens (3.0%)`, `Skills: 2.2k tokens (0.2%)`, `Messages: 70 tokens (0.0%)`, `Free space: 932.1k (93.2%)`, `Autocompact buffer: 33k tokens (3.3%)`; then `Auto-compact window: 1m tokens`; `Skills · /skills └ 15 skills · 2.2k tokens`; `/context all to expand` (screenshot 08). `[docs context-window]` `/compact [instructions]` e.g. `/compact focus on the auth bug fix`; `/autocompact [auto|<tokens>]` e.g. `/autocompact 500k`; `/config` rows `Auto-compact true`, `Idle compaction true` `[ran]`. What survives compaction: CLAUDE.md, auto memory, skill descriptions, plan file, up to 5 recently touched files re-read (files >5k tokens come back as `Referenced file` instead of `Read`), invoked skill bodies capped 5k each/25k total, background commands keep running; `SessionStart` hooks with source `compact` run. Resumed compacted sessions open at a `Conversation compacted` marker `[docs sessions]`. The literal indicator "Context left until auto-compact: N%" was **not** found in current docs or UI; the current exposure is `/context`, the `context_window.used_percentage/remaining_percentage` fields fed to the status line, and the live token counter beside the spinner (§11). `/rewind` → `Summarize from here` / `Summarize up to here` compacts part of a conversation `[docs checkpointing]`.

## 5. Diff presentation

`[ran]` The only diff rendered without a model was the theme preview (screenshot 05): line-number gutter, a full-width red-background line `2 - console.log("Hello, World!");` and a green-background line `2 + console.log("Hello, Claude!");` with a brighter word-level highlight on the changed word; `Syntax theme: Monokai Extended (ctrl+t to disable)`. So the diff style is unified, line-numbered, background-coloured, with word-level emphasis. `[docs settings-reference]` theme tokens confirm the model: `diffAdded`/`diffRemoved` (line backgrounds), `diffAddedWord`/`diffRemovedWord` (word highlight), `diffAddedDimmed`/`diffRemovedDimmed` ("the dimmed diff shown after you reject an edit"), `syntaxHighlightingDisabled`. `[docs interactive-mode]` `/diff` opens a diff panel beside the conversation in the fullscreen renderer (needs git, ≥110 cols; auto-opens at ≥144 cols once Claude edits) listing files with +/- counts, `ask` button to attach a file's diff to the next prompt, a `source` picker with per-turn views `T1, T2…`, `Ctrl+X B` cycles session/uncommitted/branch comparisons; classic renderer opens a diff dialog above the prompt. `/focus` shows only last prompt + one-line tool summary with edit diffstats + final answer. Side-by-side: not offered (not verified beyond docs). The inline `⏺ Update(file)` tool row + collapsed diff: not observed live; see §6 for the collapse mechanics.

## 6. Tool-call collapse/expansion

`[ran]` Transcript grammar observed: user/command turns are an inverse-video pill prefixed `❯` (`! ` for shell), results are indented 4 spaces; the turn ends with a dim line `✻ Worked for 0s · done 2:51 AM` / `✻ Crunched for 0s · done 2:52 AM` (random past-tense verb + elapsed + wall-clock; `showTurnDuration` setting, docs call it the "Cooked for" line). `⎿` was observed as the result connector for `/help` (`⎿  Help dialog dismissed`). `⏺` tool rows were not observed (no model reply). `[docs interactive-mode]` `Ctrl+O` toggles the transcript viewer which "expands lines that collapse by default, such as MCP calls, shown as a single `Called slack 3 times` line"; `Ctrl+E` (classic renderer) toggles show-all. `[docs fullscreen]` clicking a collapsed tool result expands it; `[` dumps the whole transcript with all tool output expanded into the terminal's native scrollback. Pasted input collapses to `[Pasted text #1 +120 lines]`; images to `[Image #N]`. The literal "… +N lines (ctrl+r to expand)" string: **not verified** for 2.1.317 (Ctrl+R is history search now; expansion is Ctrl+O/click). Subagents `[docs sub-agents]`: a delegation appears as a tool row `code-improver(Suggest code improvements)`; running subagents get a panel below the prompt with rows `name · description · token count`, nested as a tree with `(+N)`; on finish the row disappears and the footer shows `/tasks to see subagents` for 30 s. Parallel tool calls: not verified visually.

## 12. Onboarding, theme, terminal

`[ran]` Step 1: `Welcome to Claude Code v2.1.317 / Let's get started. / Choose the text style that looks best with your terminal / To change this later, run /theme` — options `Auto (match terminal)`, `Dark mode` (default ✔), `Light mode`, `Dark mode (colorblind-friendly)`, `Light mode (colorblind-friendly)`, `Dark mode (ANSI colors only)`, `Light mode (ANSI colors only)` (`/theme` later adds `New custom theme…`), with a live diff preview and `Syntax theme: Monokai Extended (ctrl+t to disable)`; `Enter to select · Esc to cancel`. ## 13. Interruption and queueing

`[docs interactive-mode]` `Esc` stops the current response or tool call; "Claude keeps the work done so far"; queued messages are sent next. `Ctrl+C` also interrupts. Cancelled tool rendering: not verified (needs model). Typing while Claude works and pressing `Enter` **queues** the message; queued and sent-but-unstarted messages show in gray; messages are delivered as soon as the current tool calls finish (same turn) or at turn end; commands and `!` commands are held until the turn ends and run in order; `Ctrl+Enter` sends queued now (interrupting if Claude is only writing text); `Up` from the first input line takes queued items back into the input box; `/btw <q>` asks a side question without interrupting. `Ctrl+B` backgrounds a long Bash command/agent; `Ctrl+X Ctrl+K` kills background subagents.

## 14. Resume

`[ran]` `claude --help`: `-c, --continue` (most recent conversation in cwd), `-r, --resume [value]` (id/name or picker), `--fork-session`, `--from-pr <n>`, `-n, --name`, `-w, --worktree`. `/resume` picker (screenshot 15): title `Resume session`, `⌕ Search…` box, project label, empty state `No conversations found in this project. / Ctrl+A to show all projects`, footer `Ctrl+A to show all projects · Ctrl+B to only show current branch · Type to search · Esc to cancel`. `[docs sessions]` rows show name/title (or summary/first prompt), time since last activity, git branch, size; keys `↑↓ Enter Space(preview) Ctrl+R rename / search Ctrl+A all projects Ctrl+W all worktrees Ctrl+B branch Esc`. Resumed sessions restore permission mode and model; compacted ones open at `Conversation compacted`; a `Resume this conversation?` dialog offers `Resume` / `Start a new conversation` when launching into an existing session. `/rename [name]` labels a session (shown on the prompt bar and terminal title); `/clear [name]` labels the conversation being closed; `/branch`, `/fork` copy a conversation. `[ran]` Esc Esc with empty input opens **Rewind**: "Restore the code and/or conversation to the point before…" listing each user turn with `No code changes`, `❯ (current)`, `Enter to continue · Esc to cancel` (screenshot 21); `[docs checkpointing]` picking a turn offers `Restore code and conversation / Restore conversation / Restore code / Summarize from here / Summarize up to here / Never mind`.

## 15. Other usability conventions

- Every panel ends with an italic/dim key legend (`Enter to confirm · Esc to cancel`, `←/→ to switch · ↓ to select · Esc to cancel`, `Type to filter · Enter/↓ to select · ↑ to tabs · Esc to clear`) `[ran]`. Panels render **above** the prompt box inside the transcript column under a bold rule; the prompt box stays in place.
- Settings are one searchable panel with tabs `Status · Config · Usage · Stats`; `/status`, `/config`, `/usage` are deep links into it `[ran]`. `/status` rows: Version, Session name (`/rename to add a name`), Session ID, Session kind, Peer address, cwd, Auth token, Model `Default (claude-opus-5-5)`, Setting sources, Auto mode server.
- Errors are one magenta line in the transcript and a persistent right-aligned status: `Not logged in · Please run /login` / `Not logged in · Run /login` `[ran]`. Docs phrasing follows "what happened · what to do": `Please run /login · API Error: 401 Invalid authentication credentials`, `Unable to connect to API. Check your internet connection`, `Connection refused — a firewall or proxy may be blocking it (ConnectionRefused)`, `Can't reach the API server — check your internet or DNS (ENOTFOUND)`, `Connection dropped (ECONNRESET)`, `Request timed out. Check your internet connection and proxy settings`, `API Error: Repeated 529 Overloaded errors`; retries are automatic `[docs errors]`. Startup warnings use `⚠`: `⚠ Remote managed settings failed to load (authentication rejected (401)) · no remote policy applied · /status for details` `[ran]`.
- `!` shell commands run locally even when the model is unavailable; the result is still appended to context and a model follow-up is attempted `[ran]`.
- Idle affordances: one-line session recap after ≥3 min away, `/recap`; `/insights` HTML report; `/doctor` setup checkup `[docs]`.
- Mouse: click to expand tool results, click options/tabs, wheel scroll, Ctrl+click paths `[docs fullscreen]`.
- Gotcha `[ran]`: inside `/config`, `Esc` clears the search filter rather than closing the panel (footer says `Esc to clear`); keystrokes meant for the prompt go into the search box.

## Patterns worth borrowing

| Pattern | Rule it embodies | MARS builder action |
|---|---|---|
| One footer line = `<mode glyph> <mode> on · <next key>` | The riskiest state (what may run without asking) is always visible, with the key to change it | Put the sandbox/approval mode in the `mars` footer and the Shell status bar; `Shift+Tab` cycles; never hide it behind a command |
| `⏸` vs `⏵⏵` glyph classes | Stop-and-ask vs proceed is readable without words — but glyphs fell back to nothing in xterm | Use the glyph **and** the word; pick glyphs that exist in DejaVu/Nerd fonts or use pi-tui's ASCII fallback |
| Permission prompt = what · why (model's description) · exact command · `Yes` / `Yes, and don't ask again for: <scope>` / `No`, `Tab to amend` | Show the full blast radius, offer a narrowly scoped persistent allow, and let the user answer with a correction | MARS proposal cards: same four parts; "don't ask again" writes a rule to a project-local file; "amend" lets the user type a note that becomes the next instruction |
| Deny rules beat everything, including bypass | Hard guardrails are not negotiable by mode | MARS sandbox policy denies are enforced in the host, not the TUI |
| Per-folder trust gate defaulting to **No, exit**, plus two-line security notes | Dangerous defaults are opt-in; the first run teaches prompt-injection risk in two sentences | Gate the first `mars` run in a repo with the same question; default to exit |
| First-run theme picker with live diff preview incl. colorblind and ANSI-only variants | Choose appearance where you can see it; accessibility is a first-class row | pi-tui theme picker with a 4-line diff sample; ship dark/light/colorblind/ANSI-only |
| `/` autocomplete with name + one-line description, 5 rows, filter as you type; `/help` tabs incl. "Custom commands" | Discoverability without leaving the prompt | Command registry with descriptions; same list drives `/help` and completion |
| `/context` category grid + `Autocompact buffer` + `/context all` | Make context cost legible and actionable | Expose MARS context breakdown per source (system, tools, skills, messages, free) with the same layout |
| `/compact [focus]`, `/autocompact <tokens>`, re-read-5-files after compaction | User-steerable summarisation with deterministic re-injection | Implement focus-string compaction and re-inject instructions/plan/last files |
| Transcript grammar: inverse pill for the user turn, 4-space-indented results, `⎿` connector, `✻ <Verb> for <t> · done <clock>` turn footer | Visual hierarchy by indentation, not boxes; cheap to render in any terminal | Adopt the same three levels in pi-tui; keep turn footers dim |
| `Ctrl+O` detailed transcript (timestamps + model per message); `[` dumps to native scrollback | Default view is terse; detail is one key away and exportable | Add a verbose toggle and a "dump to scrollback" key |
| `Esc Esc` → Rewind listing user turns with per-turn `No code changes` | Undo is anchored to the user's own prompts, with code and conversation restored separately | Snapshot the sandbox per turn; offer restore code / conversation / both |
| Queue while running; gray until started; `Ctrl+Enter` to send now; `Up` to take back | Typing never interrupts by accident | Implement a visible message queue in the TUI |
| `!` shell mode recolours the prompt border and footer | Mode change is signalled by colour across the whole input region | Same for MARS shell passthrough |
| Status line as a user script fed JSON (model, cwd, cost, context %, rate limits) | Customisation by composition, not options | Expose a `mars` status-line hook with the same JSON shape |
| Hooks: JSON on stdin, exit 2 blocks, `permissionDecision` JSON | Deterministic policy outside the model | MARS host hooks around proposals/executions with the same contract |
| Panels end with a key legend; settings are one searchable tabbed panel | Every screen is self-documenting | pi-tui panel component with mandatory footer legend |
| `/model` rows show price per Mtok and `s` for "this session only" | Cost consent at the point of choice | Required for MARS paid-model consent: show price, default to free, make paid a per-session or explicit default choice |
| Error line = "what happened · what to do" with the fixing command inline | Errors are actionable | `Not connected · Run /login`-style one-liners |

## Do not borrow / conflicts with MARS constraints

- **Auto mode as default** (classifier decides what runs). MARS executes only inside an approved sandbox and treats follow-ups as proposals the user confirms; a model-side classifier is not an approval. Keep "manual/plan" as MARS default; offer "accept edits" only inside the sandbox scope.
- **`bypassPermissions` / `--dangerously-skip-permissions`** and `dontAsk`: no unattended execution outside the sandbox; do not expose.
- **"Yes, and don't ask again" writing broad `Bash(prefix *)` rules**: fine for Claude's threat model, but MARS model output is untrusted — persist rules only for sandbox-internal actions, never for host actions, and show the saved rule.
- **Paid-by-default model picker** (Opus default at $4/$20): MARS is free-models-first; paid rows must be opt-in with explicit consent and price shown, and the default row must be a free model.
- **Many models / effort / fast-mode toggles** (`/model`, `/effort`, `/fast`, `Alt+P/T/O`): MARS has one runtime; collapse to one model picker with consent, drop effort/fast toggles unless the runtime exposes them.
- **Subagents/agent teams/worktrees/workflows/cloud (`/subtask`, `/background`, `/teleport`, `/schedule`, `/remote-control`, `/desktop`)**: single-runtime, behind a host — out of scope; do not reserve these command names unless they map to real MARS features.
- **86+ built-in commands incl. marketing items (`/stickers`, `/radio`, `/passes`, `/upgrade`, `/mobile`)**: keep the MARS list short; one description per command.
- **Hooks that let the model's own output run shell commands (`type: prompt/agent` hooks, `!` shell mode outside a sandbox)**: in MARS, `!` must execute inside the approved sandbox or be disabled.
- **Reads outside the working directory allowed by default**: MARS reads should also be sandbox-scoped.
- **Reliance on Unicode glyphs (⏸ ⏵⏵ ⎿ ⏺ ✻ ◐ ⌕) without fallback**: they silently vanished in xterm; MARS must ship ASCII fallbacks.
- **Esc semantics overloaded** (interrupt / close / decline / clear / rewind; `/config` Esc clears filter): pick one meaning per context and show it in the legend.
- **Remote managed-settings fetch at startup with a 401 warning**: MARS should not phone home for policy; policy comes from the host.
