## Architecture note (needed to read the findings)

Hermes ships **two terminal UIs plus a desktop app, all thin clients of one gateway**:

- **Classic CLI** (`hermes`, `hermes --cli`): Python, `prompt_toolkit 3.0.53` + `rich 14.3.4`, printed-scrollback layout (`display.cli_layout: modern|classic`). Since this revision it attaches to the gateway over a local WebSocket ("the same session a Desktop window, the TUI, or a Telegram topic can open at the same time"; closing prints `Detached; accepted work continues at the gateway.`). `[docs] user-guide/cli`, `[source] cli.py`, `hermes_cli/`.
- **TUI** (`hermes --tui`, or `display.interface: tui`): TypeScript React + Ink, alternate-screen, differential rendering, JSON-RPC to the Python `tui_gateway`. `[source] ui-tui/README.md`, `hermes_cli/main_tui_launch.py`.
- **Desktop** (Electron, `apps/desktop`) and a **web dashboard**; same skins, same sessions. `[docs] user-guide/desktop`.

This is the closest analogue to MARS (host + thin clients over a loopback RPC). Findings say "CLI" (classic) or "TUI" (Ink) when they differ.

## 1. Visual language

**Banner / logo.** `[ran]` Both UIs open with a 6-row block-letter `HERMES-AGENT` logo (ANSI-shadow style with an outlined drop shadow) coloured as a **three-step vertical gradient: rows 1–2 `#FFD700` bold, rows 3–4 `#FFBF00`, rows 5–6 `#CD7F32`**, then a muted tagline `☤ Nous Research · Messenger of the Digital Gods`. Below it a rounded bronze box (`╭─╮`): left column = 15-row braille-dot caduceus in gold, then `model · provider`, cwd, `Session: <8-hex>`; right column = `Available Tools` (toolset: tool, tool…), `Available Skills` grouped by category with `+N more`, footer `21 tools · 40 skills · /help for commands`. Classic puts the version in the top border (`╭─ Hermes Agent vgit.cabaf05 (2026.9.24) · stable · local cabaf053b5b4 ─╮`); the TUI puts it as a gold heading inside and makes sections collapsible (`▾ Available Tools` open, `▸ Available Skills (39) in 10 categories`, `▸ System Prompt — 24,892 chars`, `▸ MCP Servers` collapsed; click to toggle; resets each launch). `[source] ui-tui/src/banner.ts` (`LOGO_GRADIENT = [0,0,1,1,2,2]` indexes `[primary, accent, border, muted]`; `CADUC_GRADIENT = [2,2,1,1,0,0,1,1,2,2,3,3,3,3,3]`), `hermes_cli/banner.py`, `[docs] user-guide/tui#collapsible-banner-sections`. Screenshots: `hermes-tui-banner-default-skin.png`, `hermes-cli-classic-banner.png`.

## 2. Typography and glyphs

- **Fonts.** No font is selected or assumed by name in CLI/TUI code; glyphs are plain Unicode (box drawing, braille, geometric shapes, a few emoji) — **no Nerd Font private-use glyphs** found in the TUI source or observed. The Desktop app bundles **JetBrains Mono** for its terminal pane and says "Nerd Fonts render shell icons here" (opt-in). `[source] ui-tui/src/**` (grep), `[docs] user-guide/desktop#fonts`. `[ran]` Everything rendered correctly in DejaVu Sans Mono except the `ares` prompt `⚔`, which fell back to a look-alike glyph (not verified which).
- **Prompt symbol** `❯` (themeable), placeholder in muted italics (classic) / muted (TUI): `Ask anything, or type / for commands…`, rotating `Ask me anything…`, `Try "explain this codebase"`, `Try "/help" for commands`, `Find and fix a failing test`… `[ran]`, `[source] i18n/en/chrome.ts`.
- **Box drawing / borders.** Rounded `╭╮╰╯` for banner, generic overlays and tool-result boxes; **double `╔═╗`** for approval/clarify/confirm prompts and floating alerts (`FloatBox`); classic `/help` uses an ASCII `+----+` box. Tree rails `│ `, `├─ `, `└─ `; chevrons `▾ `/`▸ `; scrollbar thumb `┃`. `[source] prompts.tsx`, `overlay.tsx`, `appChrome.tsx`, `thinking.tsx`; `[ran]`.
- **Separators.** Classic modern layout: a **40-column `─` rule** opens each user message and each answer (accent) and reasoning (dim); full-width rules frame the composer; summary line `─ 3.4s · 2:46 AM`. TUI: a 3-char muted `───` between turns; status rule leads with `─`. `[ran]`, `[docs] user-guide/cli#layout-styles`.
- **Bullets / markers.** `●` tool call; `✓`/`✗` tool result; `◈` display-only event; `◇ Reference 1/2 — <label>` injected reference; `↳` sticky echo of the current prompt; `•` list bullet; `☐`/`☑` task items; `▶` collapsed `<details>`; `Σ` token total; `·` info / outcome / slash echo; `!` warning; `✕` error notice; `⚠` warning/approval; `✦ Tip:` startup tip; `⚙️` slash-command echo (classic). Full decoder ring: `[docs] reference/cli-symbols`.
- **Headings & Markdown (TUI).** `[source] ui-tui/src/components/markdown.tsx`: ATX/setext headings → **bold accent text, same size, `#` removed**; emphasis honoured (`**bold**` → bold); lists → `•` with 2-space nesting; blockquote → muted `│ ` prefix; horizontal rule → `─`×36; tables → padded 2, `─` column rules, 2-space gutters; LaTeX → Unicode math (always on). **Code blocks: no border, no background** — indent 2, optional muted label line `─ <lang>`, token colours string=accent, number=text, keyword=border, comment=muted; ```` ```diff ```` gets green/red line backgrounds; ```` ```md ```` is re-rendered as Markdown. `[ran]` see `hermes-tui-markdown-reply.png`.
- **Markdown (classic).** Final replies are **stripped**: fences, `**`/`*` wrappers and heading hashes removed, lists and `> ` kept raw ("so they render as readable terminal prose"). `[ran]` `hermes-cli-classic-markdown-stripped-reply.png`; `[docs] user-guide/cli#-shell-mode` ("Markdown stripping in final responses").

## 3. Layout density

- **Margins.** TUI transcript has a 1-col left margin; role glyph in col 1, body starts col 3 (`❯ text`, `┊  text`); tool-result boxes `marginLeft 3`, `paddingX 1`; code/tables `paddingLeft 2`. Classic prints flush-left. `[source] messageLine.tsx`, `markdown.tsx`; `[ran]`.
- **Whitespace between turns.** TUI: user row has `marginTop/Bottom 1`; one blank line between user row and the thinking/tool tree, one between tree and answer, and a short `───` + blank before the next prompt. Classic modern: blank line + 40-col rule around the user line, blank, rule, `☤ Hermes`, body, rule, summary line. `[ran]`.
- **Panel borders.** Only four bordered things exist: banner, modal overlays (round, primary), approval/alerts (double, warn), tool-result boxes (round, muted). Assistant text is never boxed in the TUI/modern CLI; the `classic` CLI layout boxes reasoning and answer panels (`display.cli_layout: classic`). `[docs] user-guide/cli#layout-styles`.
- **Input framing.** Classic: composer between two full-width `─` rules; the **top rule carries live activity on the left** (`── ⠹ Running tests · 14s ──`) **and the session title right-aligned** (`──── hello, show me markdown ─`); the status line sits **under** the composer. TUI: a single **status rule** line above a one-line `❯` composer (no box), composer grows with input; large pastes collapse to a chip `[[ … N lines … ]]` (threshold 5 lines, `LARGE_PASTE`). `[ran]`, `[source] config/limits.ts`, `[docs] user-guide/cli`.
- **Status rule / bar contents.** TUI left → right: `─ <state> │ <model> │ <ctx used/max> │ [█░░░] <pct>% │ <elapsed> │ voice off │ N sessions`, right: `─ ~/cwd (branch)` or the **session title badge** once titled (`— Here is a short **Markdown** reply from the fake model #2`). Classic status line: ` ☤ fake-echo · 180/256K · [░░░░░░░░░░] 0% · ◷ 1.1s · ↑ 52 t/s · 6m · ⏲ 3s · ✓ 4m` left, `/ commands · @ files · ! shell` affordance hints right (`◷` latency, `↑` tokens/s, `⏲` turn time, `✓` time since last completed turn). `[ran]`. Documented extra badges: `🗜️ N` compressions (TUI `cmp N`), `▶ N` bg tasks, `⚠ YOLO`, `⛓ N` subagents, `⏱ 12s/3m 45s`→`⏲` frozen, `● REC`, `◉ focus`, `📌 N` stashed drafts, `♥`. `[docs] reference/cli-symbols`, `user-guide/tui#status-line`.
- **Width behaviour.** TUI: **progressive disclosure by terminal width** — `statusBarSegments(cols)`: `<72` compact ctx (token count only); `≥72` ctx bar; `≥76` duration; `≥80` compressions; `≥84` voice; `≥88` bg; `≥92` subagent HUD (`d1/3 ⚡2/4`); `≥96` cache hit; `≥104` latency; `≥110` tps. Right label (cwd/title) gets a 3-col separator at ≥24 cols and truncates first. Classic: full ≥76 cols, compact 52–75, minimal <52 (model + duration + YOLO). Model names truncate at 26 chars. Classic modern rows are "plain rows that start with one glyph and never depend on the terminal width, so resizing can't garble earlier output". `[source] appChrome.tsx statusBarSegments`, `[docs] user-guide/cli#status-bar`. `[ran]` at 80 cols the title won over the ctx readout (`120/25 ─ Here is a short…`).

## 4. Motion

- **TUI spinners** `[source] thinking.tsx` + bundled `unicode-animations` (`ui-tui/dist/entry.js`): one braille animation is picked at random per mount from **thinking** set `helix 80 ms, breathe 100, orbit 100, dna (interval not found in bundle — not verified), waverows 90, snake 80, pulse 180` and **tool** set `cascade 60, scan 70, diagswipe 60, fillsweep 100, rain 100, columns 60, sparkle 150`; only the first cell of each frame is shown (single-column spinner) next to the `●`. Streaming cursor `▍` blinks every **420 ms**. Tool elapsed `(1.2s)` re-renders every 500 ms. After **8 s** a tool row gains a "charm": `still cooking…`, `polishing edges…`, `asking the void nicely…` (`[source] content/charms.ts`, `ui-tui/README.md`).
- **Status-bar busy indicator** (TUI): rotates kaomoji + verb every **2.5 s**, e.g. `٩( 'ω' )و pondering…`, `(◔_◔) analyzing…`; styles `display.tui_status_indicator: kaomoji | emoji (☤ 🌀 🤔 ✨ 🍵 🔮) | unicode (braille) | ascii (| / - \)`, switch with `/indicator`; "styles ship with matched glyph widths so the rest of the status bar doesn't jitter". `[docs] user-guide/tui#busy-indicator-styles`, `[ran]`.
- **Classic spinner** `[source] agent/display.py KawaiiSpinner`: frame sets `dots ⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` (default), `bounce ⠁⠂⠄⡀⢀⠠⠐⠈`, `grow ▁▂▃▄▅▆▇█▇▆▅▄▃▂`, `arrows ←↖↑↗→↘↓↙`, `star ✶✷✸✹✺✹✸✷`, `moon 🌑🌒🌓🌔🌕🌖🌗🌘`, `pulse ◜◠◝◞◡◟`, `brain 🧠💭💡✨💫🌟💡💭`, `sparkle ⁺˚*✧✦✧*˚`; **interval 0.12 s**; line format `  {left-wing} {frame} {face} {verb}... {right-wing} ({elapsed:.1f}s)`; 15 verbs (`pondering, contemplating, musing, cogitating, ruminating, deliberating, mulling, reflecting, processing, reasoning, analyzing, computing, synthesizing, formulating, brainstorming`); faces `(｡◕‿◕｡) (◕‿◕✿) ٩(◕‿◕｡)۶ …` waiting, `(｡•́︿•̀｡) (◔_◔) (¬‿¬) ( •_•)>⌐■-■ (⌐■_■) … ಠ_ಠ` thinking. Docs example: `  ◜ (｡•́︿•̀｡) pondering... (1.2s)`. In the modern layout the spinner lives **only in the composer's top rule**; "no spinner row is printed into the scrollback". `[docs] user-guide/cli#tool-progress-display`.
- **Streaming.** TUI streams assistant text through `StreamingMd` with bounded live tail (`LIVE_RENDER_MAX_CHARS 16 000`, `LIVE_RENDER_MAX_LINES 240`, label "showing live tail … omitted N lines"); reasoning streams inline while active. Classic streams reasoning live and ends with `∴ Thought for 3s · <title>`. `[source] lib/text.ts`, `config/limits.ts`; `[docs] cli#layout-styles`.
- **Progress bars.** Context fill `[██████░░░░] 6%` (`█`/`░`, 10 cells; `~` prefix = estimate), colour thresholds green <50 %, yellow 50–80, orange 80–95, red ≥95. Subagent sparkline `▁▂▃▄▅▆▇█`. `[docs] cli#status-bar`, `reference/cli-symbols`.
- **Disabling animation.** Non-TTY → spinner logs one line, no frames; `HERMES_SPINNER_PAUSE=1` pauses (set automatically during approval prompts); `/indicator ascii`; `--native` disables mouse tracking/alt screen; `hermes journey --no-color`. No single global "reduce motion" switch found (not verified beyond grep). `[source] agent/display.py`, `tools/approval_prompt.py`.

## 5. Thinking display, tool calls, tool output

- **Tree model (TUI).** Under each user row a tree: `├─ ▸ Thinking  ~25 tokens` · `├─ ▾ Tool calls (1)  ~13 tokens` · `│  └─ ● Terminal("echo hello from the fake tool + 1 command") (0.1s)` · `└─ Σ ~38 total`; optional panels `Spawn tree (N)` (subagents, with sparkline and `(/agents)`) and `Activity (N)` (`·` info / `!` warn / `✗` error rows, only the **last 4** kept). An outcome line `· <outcome>` may follow. `[source] thinking.tsx`, `i18n/en/chatBits.ts`; `[ran]` `hermes-tui-thinking-toolcalls-tree.png`.
- **Modes.** `DetailsMode = hidden | collapsed | expanded` globally (`display.details_mode`, `/details <mode|cycle>`) with **per-section overrides** `display.sections.{thinking,tools,subagents,activity}` / `/details <section> <mode|reset>`. Shipped defaults: thinking **expanded**, tools **expanded**, subagents → global (collapsed), activity **hidden** ("ambient meta … is noise for most day-to-day use; tool failures still render inline on the failing tool row; ambient errors/warnings surface via a floating-alert backstop when every panel is hidden"). `collapsed` = auto-open while reasoning streams, auto-close when it ends. Chevrons are clickable; Shift/Ctrl-click expands all. `[source] domain/details.ts`, `thinking.tsx`; `[docs] user-guide/tui#configuration`. `[ran]` after the turn the Thinking panel showed collapsed with `~25 tokens` while Tool calls stayed open.
- **Thinking text.** Rendered in `color.thinking` (= muted), bold+text colour only while live; `cleanThinkingText` strips status-verb lines; preview mode caps at `THINKING_COT_MAX = 160` chars; `full` shows bounded live tail. Legacy modes `collapsed|truncated|full`. `[source] lib/text.ts`, `types.ts`.
- **Tool call rows.** `●` in tool colour + `toolTrailLabel` (underscores → Title Case: `read_file` → `Read File`) + `("<compactPreview ≤64 chars>")` + dim `(elapsed)`; shell commands compact to `"first cmd + N command"`. Details rows (`Args:` …) are dim/muted; failed rows get `✗` in error colour; while waiting on approval a tiny braille spinner sits between `●` and the label. Classic modern: one emoji-led line per finished tool (`📖 Read calc.py`, `🔧 Patch  0.2s`, `✗ $ pytest -q  0.4s [exit 1]`) with an edit's diff under `│` rails; `/verbose` cycles `off → new → all → verbose`; `display.tool_preview_length` (default 0 = unlimited). `[source] lib/text.ts`, `thinking.tsx`; `[docs] cli#layout-styles`, `cli#tool-progress-display`.
- **Tool output.** TUI tool-role messages render in a **round, muted-border box** (`marginLeft 3`, `paddingX 1`), one-line compacted preview, `(empty tool result)` when empty; verbose trail capped `VERBOSE_TRAIL_MAX_CHARS 800 / 12 lines`. System messages > `SYSTEM_COLLAPSE_CHARS 400` collapse to first line + `— N chars` with a chevron. User messages > `LONG_MSG 300` show `[long message]`. History capped `MAX_HISTORY 800` entries. `[source] messageLine.tsx`, `config/limits.ts`.
- **Reasoning summary (classic).** `∴ Thought for 3s · Planning the change` line replaces the streamed block; `/reasoning [level|show|hide|full|clamp]`. `[docs] cli#layout-styles`, `reference/slash-commands`.

## 6. Interaction

- **Slash commands.** Typing `/` opens autocomplete (classic inline dropdown; TUI **floating panel with descriptions**). ## 7. Memory / skills / curator surfaces

## 8. Messaging gateways / web UI — one session, many surfaces

## 9. Calmness under load

- Per-section visibility with **activity hidden by default**, subagents collapsed, failures still inline; floating-alert backstop shows only the last two non-info alerts when all panels are hidden. `[source] domain/details.ts`, `thinking.tsx`.
- Hard caps everywhere: live tail 16 000 chars / 240 lines with an "omitted" label; verbose trail 800 chars / 12 lines; thinking preview 160 chars; tool preview 64 chars; system messages > 400 chars collapsed; activity panel last 4; history 800. `[source] config/limits.ts`.
- Spinner confined to one line (composer top rule / status rule); **no spinner frames in scrollback**; non-TTY prints once. `[docs] cli#layout-styles`, `[source] agent/display.py`.
- Width-independent one-glyph rows so resize never garbles history; status segments drop by priority at narrow widths; indicator glyph widths matched to avoid jitter. `[docs] cli`, `tui`; `[source] appChrome.tsx`.
- `/focus` ("show only your prompt and the final response"), `/verbose off`, `tool_progress: log`, `accumulate` bubble editing on chat platforms, `display.memory_notifications: off`. `[docs]`.
- Update cadence: stream cursor 420 ms, tool elapsed 500 ms, kaomoji 2.5 s, braille 60–180 ms, legacy spinner 120 ms. `[source]`.

## 10. Conflicts with Claude Code / Codex conventions (plain list)

Hermes facts below are `[ran]`/`[source]`/`[docs]` as cited in sections 1–9; the Claude Code / Codex comparisons are from general product knowledge, not verified in this session.

1. **Default approval choice is Deny on Enter (classic)**; the TUI pre-selects `Allow once`. Claude Code/Codex pre-select "Yes" for the common case. Also offers **`Always allow`** (persistent allowlist) and `/yolo` / `--yolo` (skip every prompt) plus `/approvals smart|off` — more permissive than Codex's sandbox-first stance.
2. **Interrupt key semantics**: `Ctrl+C` first clears a draft, then interrupts, and **double-press exits**; `Esc` does *not* interrupt (it is `Esc Esc` = discard draft, `Esc` = deny approval / close overlay). Claude Code uses `Esc` to interrupt and `Ctrl+C` to quit.
3. **Typing while busy redirects the turn (classic default `interrupt`)** instead of queuing; TUI defaults to `queue`. Claude Code queues.
4. **Ctrl+D leaves the turn running on the gateway** and detaches; closing the terminal does not cancel work.
5. `!cmd` shell escape and `{!cmd}` interpolation run on the **host, not the sandboxed backend**, and `!` output never enters the transcript.
6. Markdown is **stripped** in classic final replies (no bold, no fences) — unlike Claude Code/Codex which render it.
7. Heavy personality by default: kaomoji faces, "Messenger of the Digital Gods", `(^_^)? Available Commands`, pets (`/pet`), fortunes, affection flash `♥`, "asking the void nicely…" charms.
8. Two different terminal front-ends with partially divergent chrome (status under vs above composer, boxed vs unboxed).
9. Session title auto-derived from the first reply, raw Markdown asterisks included (`Here is a short **Markdown** reply… #2`) `[ran]`.
10. Slash surface is very large (≈100 commands + skills); `/help` is a long panel rather than a short card.
11. `Tab` is overloaded (completion, ghost-text accept, queue while busy).
12. Telemetry opt-in and a Nous-Portal OAuth "Quick Setup (recommended)" path in first-run — provider/billing commands (`/topup`, `/subscription`, `/login`) live inside the chat UI.

## Patterns worth borrowing

| Pattern (rule it embodies) | What a MARS builder does |
|---|---|
| **Seed palette + derived tones + contrast floors** (`theme.ts`): author ~15 seeds, derive muted/label/surface/selection, auto-lift for light terminals. Rule: themes are data, legibility is enforced by code. | Define `mars` theme as seed tokens (primary/accent/border/text/ok/warn/error/status*) in a YAML/TS skin file; derive secondary tones with the same mix/desaturate ladder; detect light bg via `COLORFGBG` → OSC 11 and switch seeds. Ship skins as files users can drop in, never shadowing built-ins. |
| **One-glyph, width-independent transcript rows** (`❯` user, `┊` assistant rail, `●` tool, `✗`/`✓` result, `◈` event, `∴` thought summary). Rule: history must survive resize; the glyph *is* the role colour. | In `pi-tui`, render each row as `glyph + 1 space + body` with no boxes around assistant text; reserve boxes for the banner, modals and (muted) tool results only. Keep a published symbols glossary like `cli-symbols.md`. |
| **Tree-shaped turn summary** (`├─ ▸ Thinking ~N tokens / ├─ ▾ Tool calls (N) / └─ Σ ~N total`) with per-section modes and opinionated defaults (activity hidden, failures inline). | Model MARS turn chrome as sections `{thinking, tools, subagents, activity}` with `hidden|collapsed|expanded`, config + `/details`; show token/cost totals as a `Σ` leaf; keep errors on the failing row even when the panel is hidden. |
| **Hard output budgets with explicit "omitted" labels** (16k chars/240 lines live tail, 64-char tool preview, 400-char system collapse, last-4 activity). | Put the same constants in one `limits.ts` for the TUI and reuse for MARS Shell; always say what was omitted instead of silently truncating. |
| **Spinner lives in one line of chrome, never in scrollback**; busy indicator = verb + elapsed, matched widths. | Put MARS progress in the composer's top rule / status rule only; render `⠋ <verb>… · 14s` with fixed-width verb slots; no progress rows in the transcript. |
| **Progressive status-bar disclosure by column width** with an explicit breakpoint table. | Give MARS status segments priorities and drop them in order (<72 compact ctx, ≥76 duration, ≥88 bg, ≥92 subagents, ≥104 latency, ≥110 tok/s). |
| **Composer top rule carries live activity (left) + session title (right)** and the status line sits under the composer with "keys that do something right now" on the right (`enter interrupt · tab queue · ctrl+c stop`). | Use the rule above the input for *state*, the line below for *facts + available keys*; change the key hints with state (idle → `/ commands · @ files · ! shell`). |
| **Approval panel as a numbered, bordered modal** with the exact command text, quick-pick digits, paging for long commands, and the spinner paused meanwhile. | For MARS proposals: double-border warn panel, `⚠ approval required · <why>`, full command, numbered options, `Esc = deny`, `v` to page. Fail closed on timeout/disconnect (Hermes does). |
| **Staging queue for background writes** (`/memory pending|approve|reject`, `/skills pending|diff|approve`, `[auto]` tag, one-line gist inline + full diff out-of-band). | MARS curator/memory proposals: list with ids + gists, `diff` command for full content, approve/reject `<id|all>`, approval pinned to content hash. Surface a one-line `💾`-style notice when a background service changes state, configurable `off|on|verbose`. |
| **Durable gateway-side queue shared by all clients** (`queued (N)` panel, edit/delete queued prompts, `Ctrl+X` to delete). | Keep MARS's queue in the host; every client (TUI, Shell) renders the same `queued (N)` panel from RPC. |
| **Live session switcher** (`Ctrl+X`): idle/starting/waiting/working glyphs, `✎ draft`, `+new` row that dispatches a prompt. | Add the same overlay to the `mars` TUI; reuse the glyph set for MARS Shell's sidebar. |
| **Banner as a collapsible capability inventory** (tools open, skills/system prompt/MCP collapsed, `N tools · N skills · /help`), plus one rotating `✦ Tip:` line. | MARS banner: model + provider + cost tier, sandbox, cwd (branch), session id, collapsible tools/skills, one tip. |
| **Markdown without boxes**: bold-accent headings, `•` bullets, code indented 2 with a muted `─ lang` label, `│` quotes, diff blocks coloured. | Adopt for `pi-tui` Markdown renderer: no code borders/backgrounds; label the language; colour diffs. |
| **Skin switch repaints live** (`/skin ares`) and the Desktop lists CLI skins next to its own themes. | One skin schema shared by `mars` TUI and MARS Shell (Shell adds `customCSS`). |

## Do not borrow / conflicts with MARS constraints

| Hermes behaviour | Why it conflicts with MARS | Do instead |
|---|---|---|
| `Always allow` + `/yolo` + `/approvals off`, `⚠ YOLO` badge as the only guard | MARS: model output is untrusted; follow-up actions are proposals the user confirms. A persistent allowlist or global auto-approve defeats that. | Offer `once` / `this session` only; no permanent allow, no YOLO. Keep the badge idea for any *elevated* session state. |
| `!cmd` / `{!cmd}` run on the **host**, outside the backend; shell output interpolated into prompts | MARS: execution only inside an approved sandbox. | If a shell escape exists, route it through the sandbox and label it as such; no inline interpolation into model input. |
| Classic default **Enter = Deny** vs TUI default **Allow once** (inconsistent), `Esc` = deny | Inconsistent defaults across surfaces breaks the "one contract" goal. | Pick one default per MARS risk class and keep it identical in TUI and Shell. |
| Hermes runs an **in-process gateway per TUI** (and Desktop/dashboard spawn their own) | MARS has a single agent runtime (Oh My Pi) behind one host; clients must be thin. | `mars` TUI and MARS Shell attach to the existing loopback workbench RPC only. |
| Nous Portal "Quick Setup (recommended)", `/topup`, `/subscription`, `/login`, `Remote Spending` prompts inside the chat | MARS: free models first, paid only with explicit consent; billing UI in the agent surface nudges toward paid. | Show provider/cost tier in the status bar; paid models require an explicit, separate consent step; no purchase flows in the TUI. |
| Classic CLI **strips Markdown** from final replies | Loses structure the user asked for; Claude Code/Codex render it. | Render Markdown (TUI style). |
| Busy-input default `interrupt` (redirect the running turn by just typing) | Surprising for Claude Code/Codex users; can cancel sandbox work implicitly. | Default to `queue`; make redirect explicit (`/steer`, `/stop`). |
| `Ctrl+C` double-press exits; `Esc` doesn't interrupt | Conflicts with Claude Code muscle memory (`Esc` interrupt). | `Esc` interrupts, `Ctrl+C` twice exits, keep `Esc Esc` discard-draft optional. |
| Kaomoji/emoji personality, pets, fortunes, "void" charms | Noise; fonts without those glyphs break alignment (observed `⚔` fallback). | Braille-only spinners, plain verbs, ASCII fallback style. |
| Session title auto-derived from reply text incl. raw `**` | Looks broken in the status rule. | Derive titles from the user prompt, strip Markdown, cap length. |
| ~100 slash commands + skills as commands | Discoverability cost. | Small core set + palette; keep skill invocation under one `/skill` namespace. |
| Telemetry opt-in dialog on first run | Not part of MARS's contract; adds a first-run step. | None. |
