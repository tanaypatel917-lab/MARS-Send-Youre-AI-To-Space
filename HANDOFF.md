## Decisions

- UI (from `documentation/UI_PROMPT.md`): every MARS client — interactive `mars session`, MARS Shell, VS Code — is a projection over `tasks.events`/`tasks.artifact`/`tasks.diff` and never a runtime; the terminal client is built from `@oh-my-pi/pi-tui` components and theme JSON (`src/theme/dark.json`, `light.json` are the token source of truth), with `@oh-my-pi/pi-coding-agent`/`pi-agent-core`/`pi-ai` imports forbidden in client code by lint. Usability conventions were taken from Codex CLI and Claude Code (approval card anatomy with `✔/✗` decision log, collapsed tool output with explicit expansion, footer hints by state, `Tab` queue vs `Enter` steer); visual language from Hermes and Oh My Pi. Where they conflict the document says which side won and why (§1.1). No `Full Access`/bypass mode and no LLM-as-approver exist in any client; paid models and screen capture are opt-in cards.
- Research correction: the Codex CLI source at `rust-v0.166.0` has no `codex://review` link or follow-up syntax (only `codex://threads/*`); the output format's `codex://review`/`:codex-followup` aliases stay as import aliases for text written against the earlier third-party description and are not presented as Codex compatibility.
- One owner per responsibility (spec section 3). Oh My Pi stays the only live session/tool owner; everything else connects through host-bound tools and contracts.
- `mars-platform` and this repo both ship a `@mars/memory`. This repo's `packages/memory` (scoped durable MemoryService + journal index) is the one wired into sessions; the Hermes threat scanner and proposal API were ported into it in Milestone 3.
- `mars-platform` is reference-only once Milestone 3 lands; it is not modified, and future changes to memory, skills and review happen in this repo.
- Background review calls models through the provider registry (`selectExecutionModel`, free-first, refuses paid), not through an OpenAI-compatible endpoint env (`MARS_REVIEW_*` does not exist here).
- Team Chat never becomes a second owner of tasks, artifacts or verification: the chat side stores workbench ids and re-reads host-owned state through `tasks.inspect`/`tasks.diff`/`tasks.evidence`. The tenant is `team_id`; `workspace` keeps meaning a workbench private copy.
- `launch_key` lives in the `@mars/tasks` store (`launch_keys` table, same immediate transaction as the task row) rather than being derived into a `request_id`, so the existing request-id idempotency rows and their replay bytes are untouched when the key is absent and a key reused for a different canonical task is a `conflict` rather than a second task.
- The diff digest is an additive optional `digest` on `tasks.diff` rather than a digest-only method: one field, both strict schemas updated together, older servers' results still validate. `tasks.evidence` is the only new method and is read-only; `verified` is always copied from the stored watch record, never computed from the current workspace, and staleness is a separate flag keyed on `(workspace_id, workspace_revision, diff_sha256)` — a delegated child's evidence is stamped with the child's private workspace and is never fresh for the parent tree. Binary patches carry an `index <sha>..<sha>` line so the digest changes with binary content.
- Memory proposals are scoped to the exact review context and revision-fenced (`expected_revision` checked at submission and again at acceptance); skill proposals likewise carry `expectedRevision`. Review can only submit; humans/host accept.
- The SKILL.md frontmatter parser is a flat `key: value` subset with no YAML dependency (anchors, aliases, block scalars, nesting rejected).
- Free-first model routing (`allowPaid: false`) stays the default; no live provider keys are stored in repos.
- The MARS Output Format is MARS-owned (`documentation/OUTPUT_FORMAT.md`), modelled on an unverified description of a third-party format; it claims no compatibility with OpenAI products. `codex://review` and `:codex-followup` are accepted on parse as import aliases; the serializer preserves a follow-up's original tag and never rewrites review links inside Markdown text.
- Model output is untrusted: writing-block addresses are validated against addresses the user supplied in the request, `app://` connector ids against the host registry, review ranges against a line cap. Follow-ups, app triggers and review links are proposals; the host never runs a tool because the model emitted a link.
- `OUTPUT_FORMAT_PROMPT` is appended once to the execution runtime system prompt, so coordinator, workers, reviewer and delegated children all receive it. The research worker's extraction model is deliberately excluded: its contract is a single JSON object, not Markdown.
- Claims of "improvement" require independent evidence (holdout, baseline, cost) — a finished job is not evidence (spec sections 16-17).
- **`completed` ≠ verified.** `completed` stays the execution status (the session ended normally). Verification is a host-owned verdict: required checks are fixed at launch outside the model's control (`required_checks` in `tasks.start`, frozen in `launch.json`), evaluated by the workbench host after the run against one immutable candidate revision (the workspace tree digest, re-read before and after the checks), and persisted as a `VerificationEvidenceRecord` task event. Missing or wrong output is `failed`, a timed-out or unavailable verifier is `inconclusive` (never `passed`), a run without evidence is Unverified, and a candidate that changed after a pass is Verification stale. Every surface that says "Verified" goes through `verificationStateFor(candidateRevision, records)`; Team Chat result sharing consumes the same verdict. Textual tool calls in assistant text are never parsed or executed — they are recorded as a diagnostic on the verdict (`documentation/evidence/ollama-textual-tool-call.md`).
- Milestone 4 layout: Harbor, mini-swe-agent and GEPA run in a pinned Python 3.12 venv (`harbor==0.25.0`, `mini-swe-agent==2.4.6`, `gepa==0.1.4`, no DSPy) launched and bounded by Bun-side services; Harbor result/reward/error records are parsed, exit codes are never trusted; Terminal-Bench 2 is consumed through Harbor datasets pinned to task commits (`sources/manifest.json` `terminal-bench-2`), never vendored.
- Prompt optimisation scores only through the additive `PromptScoringBackend` contract (`train`/`validation` splits; no holdout value exists in the type), final-holdout ids live in a separate record, and GEPA candidates are stored proposals (`draft -> proposed -> accepted|rejected|archived`); "no improvement" is a valid reported outcome. The live `SYSTEM_PROMPT` is never mutated by a run.
- Local models: register them with `mars models add --provider ollama ...`; nothing local goes into `BUILTIN_MODELS` because the default route would then hit an unreachable endpoint. Finding recorded in `documentation/evidence/local-model-run.txt`: with `qwen3-coder:30b` the fixed MARS system prompt deterministically produces text-form tool calls that Ollama does not parse, so a real-model comparison on CPU needs an accepted prompt proposal or another model.
- watch-skill (MIT, Python 3.11+) is an external runtime, never a second loop: `@mars/watch` drives the CLI as an argv-only subprocess with an env allowlist, bounded roots, offline flags and a doctor gate (`version` must be 1.4.3, `doctor --no-fix --json` must be ok); if either fails the tools are `unavailable`/`inconclusive`, never `pass`. THE LOOP is `visual_advisory` and never `verified`; only a `verify` run with a passed required deterministic check at `deterministic_local`/`isolated_local` is. Screen/window capture is off for every role until the user sets `allow_screen_capture`; which roles may capture by default is an open product decision for the owner. `remote_attested` is refused because upstream does not implement it.
- graphify (Apache-2.0, Python 3.10+) is an external runtime like watch-skill, never a second loop or a memory owner: `@mars/knowledge-graph` runs only `graphify --version` and `extract --code-only` argv-only with an env allowlist (HOME/`GRAPHIFY_OUT`/cache pinned to a host-private root, proxy variables closed), deletes the raw output (it contains the absolute scan root) and stores a normalised, relative-path-only artifact keyed by scope + workspace and fenced by the workspace revision. Wrong version → `unavailable`; empty graph, missing/invalid `graph.json`, crash or timeout → `failed` with nothing stored; a query against another revision → `stale`, never an answer from the old graph. Children do not get graph tools (coordinator only) until there is a need.
- The Obsidian vault is a mirror, not a store: SQLite (`@mars/memory`) and the `SkillStore` keep history and search; the vault is rebuilt by `export` and edits come back only as proposals (`submitProposal` on both stores, revision-fenced against the exported revision) that the owner accepts or rejects. Graph notes in the vault are derived and read-only (edits are reported, never proposed). Vault text re-read by anything is untrusted and passes `scanThreat` before a proposal exists. MARS has no separate project-note store, so project notes are generated index notes per `project_id`.
- Codex/Claude conventions are formats and host-bound tools, never a loop: openai/codex (Apache-2.0) code is ported with headers naming the upstream file and revision plus `packages/codex-tools/{NOTICE,third_party/codex}`; anthropics/claude-code is proprietary, so only file names, frontmatter keys, event names and `$ARGUMENTS` are mirrored and no source was read. Repository text is bounded and labelled (instructions frozen whole-or-omitted, skills untrusted), hooks are argv arrays that run only through the sandboxed execute approval (no shell strings, no stdin JSON, no `danger-full-access` equivalent), `mars_apply_patch` writes only through the workspace provider, and conventions are read once from the trusted source checkout (the provider never copies `.mars/` into task workspaces, so a model cannot edit its own hooks).
- Team Chat is a new owner for people, team membership and conversations, never a second owner of tasks, artifacts or verification, and never a second model loop. The plan's "workspace" (tenant) is `team_id` in code because `Scope.workspace_id`/`WorkspaceRef` already mean a workbench private copy. The PR 1 prototype lives in `apps/vscode` as a second, flag-guarded webview view (`mars.teamChat.enabled`, default off) under the same CSP/`textContent`/strict-schema model; it is fed by `FixtureTeamService` in `@mars/team-chat` and has no path to `tasks.*`, workspaces or a network. Code references are committed Git objects (`repo_id` + full 40-hex SHA + normalized path + range) resolved per viewer and failing closed to `Restricted reference`; a folder path or repo name is never an access identifier; the viewer id is never a client-supplied request field. `packages/collaboration` rooms stay agent-only; only their idempotency/sequence patterns are copied.
- Vendored upstream text is allowed when copied verbatim with its license and a NOTICE (`skills/vendor/watch-skill`); the skill service (`@mars/skills`, ported on a separate branch) loads it as a read-only library — see the loader note there.
- Screen capture shipped with #49 as off for every role; the owner has not widened it. Any change is a `WatchPolicy` default, not a per-tool exception.
- Outside tooling is adopted by licence: Apache-2.0 code (openai/codex `apply_patch`, graphify) may be ported or pinned with attribution and NOTICE; Claude Code is proprietary, so only its file formats and conventions are implemented; Obsidian is proprietary, so the vault is plain Markdown we write ourselves. SQLite memory and the skill store stay the only owners; graphs and vaults are derived or mirrors.
- OmniRoute (cheaper-inference/OmniRoute, MIT) is approved by the owner as an optional, self-hosted, loopback-bound provider gateway. MARS keeps model policy and paid consent; OmniRoute's MCP/A2A features, web-session providers (ChatGPT/Claude/Grok/Gemini Web) and anything it flags as terms-risk are excluded by default; its token-compression savings are unverified and off.
- UI direction from the owner: usability of Claude Code and Codex, visual design of Hermes and Oh My Pi, for both the terminal client and the MARS Shell desktop app. `documentation/UI_PROMPT.md` (in progress) is the first MARS Shell specification.
- Team Chat code references are `{repo_id, commit_sha, path, line_start?, line_end?}` and nothing else: `commit_sha` is a full 40-hex commit (never a ref or abbreviation), `path` is kept byte-verbatim (git never normalises Unicode names) and must pass the `checkRelativePath` rules plus the memory invisible-code-point denylist in both its raw and NFC form (sync tests in `packages/code-refs`), and `repo_id` is an opaque id the HOST maps to a repository directory at startup (`createRepoRegistry`) — never a path, a hash of a path, or a repository name, and never registerable or discoverable from a client. `@mars/code-refs` resolves committed objects only (`rev-parse --verify <sha>^{commit}`, `ls-tree`, `cat-file` by blob id; working tree, index and branches are never consulted) through argv-only `git` with the watch/graphify env allowlist, `-c` overrides that neutralise repository-local config (`core.fsmonitor`, `core.hooksPath`, pager/editor/ssh/askpass/credential helpers, `protocol.allow=never`), bounded output and timeouts, and returns fixed states (`unavailable`, `is_directory`, `unsupported_symlink`, `unsupported_submodule`, `oversized`, `binary`, `range_out_of_bounds`, `error`) with no directory or absolute path anywhere. **The package does no authorization**: the chat service decides who may see a `repo_id` before calling it and renders a `restricted` chip (no path, sha or excerpt) otherwise. Defaults: 1 MiB blob, 400-line range, 10 s timeout, ≤ 100 search hits, 50 000 scanned entries. `GitRangeReferenceSchema` is defined once in `packages/contracts/src/team.ts` and re-exported by the package (PR 4 service half). Verified offline only (temporary `git init` repositories in tests; CI runners provide `git`, local runs without `git` skip with a warning).

- **OmniRoute is one provider target, never the policy owner.** It is reached through the existing `openai-compatible` adapter (`ProviderConfig.kind` unchanged); `@mars/providers` only gained `AdapterOptions.headers` and `ModelProviderRegistry.extend()` (in-memory additions with an optional default adapter factory the router falls back to). The MARS-owned catalog (`catalog/free-tier-catalog.json`, parsed as text from upstream `freeModelCatalog.data.ts` + `freeTierCatalog.ts` + web-cookie/no-auth registries; no upstream code vendored or executed) decides what is free; the adapter-factory guard refuses any OmniRoute model that is not a free, non-excluded catalog entry unless MARS classified it as paid under `allowPaid` with explicit selection, and sends `X-MARS-Paid-Consent: granted|absent`. Default exclusions: web-session (35 web-cookie ids incl. ChatGPT/Claude/Grok/Gemini Web), browser-session (`duckduckgo-web`, `cloudflare-playground`, `veoaifree-web`), every verdict other than `ok` (`avoid` can never be opted in), discontinued tiers, MCP/A2A (never called), compression (not exposed, unverified). Capabilities are unknown offline, so catalog models are tool-less until one `GET /v1/models` discovery at serve time; the execution runtime therefore never selects them without discovery. `--omniroute-start` spawns `omniroute` only on `127.0.0.1` with an env allowlist, requires `--version` to report 3.8.52, discards child output, and stops with SIGTERM then SIGKILL. `OMNIROUTE_API_KEY` is OmniRoute's gateway key by name; upstream credentials stay in `~/.omniroute`. Review fixes (#55): discovered-but-unlisted catalog models are dropped (404 would stop fallback); a gateway is ready/attachable only when `/v1/models` answers authorized (401 fails startup); plain `http` only on loopback, remote needs `https`; `paidConsent` is an explicit option defaulting to `false` (`allowPaid` alone is never task consent); the registry extension carries the probe's env so `OMNIROUTE_API_KEY` resolves consistently.

- Team Chat (PR 2): the tenant is `team_id` — "workspace" keeps meaning a workbench private copy. `user_id` is never accepted from a client; it comes from the `Authenticator` (dev token map only; GitHub OAuth/OIDC/MARS accounts is an owner decision). Conversation-scoped calls answer `not_found` for both "absent" and "not yours" (existence never leaks); `forbidden` is team-level denial only. `@mars/team` carries the repo's first migration ledger (`TEAM_MIGRATIONS`, forward-only, private to that store); the other stores still reject foreign format versions. Pilot = loopback Bun + SQLite with a Postgres-portable schema. Team Chat pulls multi-user isolation forward from milestone 9; the team service never calls a model (@MARS answers will run as workbench sessions) and never owns task state.
- Team Chat (PR 3, service half): streaming is SSE on a second loopback route (`POST /v1/stream`, same auth/Host/Origin/content-type checks and envelope as `/v1/rpc`; `GET` stays `not_found`) whose frames are outbox metadata only. Live delivery is "wake and re-poll": a post-commit store notice marks the conversation dirty and the stream re-runs the membership-filtered `events.poll` query from its own cursors, so backfill and live frames share one query (no gap, no duplicate) and per-connection state is bounded by the cursor count. Revocation (`remove_member`, `conversations.leave`, host `removeTeamMember`) closes the user's streams synchronously before the removing call answers. Search is `LIKE` (escaped, ASCII case-insensitive, Postgres-portable), not FTS5 — Bun 1.4.4 ships FTS5 but token semantics and shadow tables were judged wrong for a pilot; membership is a SQL join on active participation and `seq > joined_seq` before any body is read. Reaction keys use the memory invisible-code-point denylist literally (U+FE0F rejected; clients strip VS16). Rate limits and open-stream counts are per serving process.
- Team Chat (PR 4, service half): repo access is host-administered data (`repos`, `repo_access` tables via `store.setRepo`/`setRepoAccess`/`revokeRepoAccess`), never granted over RPC in the pilot; `repo_id` is the opaque registry id and the team store holds no path. A reference is created once (`validateLocator` → one resolve through the host registry → `referenceDigest` id, dedupe per team; `unavailable` objects cannot be attached) and every read re-authorizes: team membership + visibility through a message the viewer can see + current `repo_access`, re-read per call with no cache. Member without repo access → exactly `{state: "restricted"}` / `{reference_id, restricted: true}`; absent or inaccessible repo/reference → `not_found` (the #60 choice); events carry no reference fields; the server's `validateResult` re-checks every chip, preview and search hit against the store. `blob_sha256` is the SHA-256 of the excerpt at creation (null for `binary`/`oversized`). Resolve rate limit answers `unavailable` because the RPC vocabulary is frozen. `messages.search` (PR 3), reply excerpts and @MARS/result cards (PR 5–6) must use the same chip projection when they land.
- Team Chat (PR 6, chat half): the team service never talks to a workbench — the client calls `tasks.create`/`tasks.evidence` with the user's own connection and the service stores ids and cards. Provenance is frozen at draft time; the `launch_key` is minted by the service and replayed so an interrupted confirm cannot start a second task. A result card is attested (`attested_by`, `evidence_sha256`), never verified by the service: `verified: true` requires a submitted record with `verified && !stale` for the same `diff_sha256`/`workspace_revision`, otherwise `verified_reason` ∈ `missing|stale|failed|inconclusive|skipped`; `run_status`, `verified`, `export_status` and `git_status` (`unknown`) stay separate fields. A re-share with a different digest marks earlier cards `stale` at read time; posted content is immutable. Other members see link status and provenance only — never the requester's scope/task ids or launch key. Artifact shares answer `unavailable` until the artifact access gate (later PR). `run_status` is passed by the client from `tasks.inspect` because `tasks.evidence` does not carry it (documented follow-up, workbench untouched).
