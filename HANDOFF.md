## Milestone 2: shared research allowance (first offline slice)

- Research admission (`packages/research/src/service.ts`, `taskResearchCommitment`) now checks the sum across a task's jobs, not each job alone: queued/running jobs hold their whole `max_tokens`/`max_usd`, finished jobs count reported usage (or their whole budget when usage was never reported), never-started jobs count nothing. The check runs inside the same immediate SQLite transaction as the insert, so concurrent submits cannot both fit, and it is derived from durable rows, so retries, lease handovers and restarts neither double-count nor refill. A job that would exceed the task allowance is refused with `budget_exceeded`.
- Shared task budget: foreground, research and delegation draw tokens/USD from the durable `budget_holds` ledger in `@mars/tasks`. Concurrency is shared through `concurrency_slots` (`acquireSlot`/`releaseSlot`): each running research job and delegated child holds one slot with a lease-length expiry renewed on heartbeat, one slot of `max_concurrency` is always left for the foreground run, and a job without a free slot is returned to its queue unchanged and retried. A research model call that fails or times out is charged its whole reservation, since it may still have been billed. One fixed deadline: the task store's `fixDeadline` sets the task's absolute deadline once, at first launch (`now + max_duration_ms`; `startRun` marks the task running and fixes it in one transaction), and the collaboration room, the foreground runtime ledger (new or resumed) and research all stop at it; a resume never moves it. When a task's room closes (drained, cancelled, or found closed by a restarted host via `unsettledBudgetHolds`), the host settles the `delegation` hold with `settleBudget` to what the room charged its children (plus any reservation it still reports outstanding), so the unspent pool returns to the foreground run and research; a draining room settles when its last child finishes. The first settle sets the hold; later settles (retries, concurrent hosts) only raise it, so spend is never undercounted; any successful `reserveBudget` on the key reopens it, even one the hold already covers.

## S3: edit-format benchmark (MARS vs stock omp) and evidence-based edit-format selection (offline)

`mars bench edit-formats` (`apps/cli/src/bench.ts`, `packages/evaluation/src/edit-benchmark/`) runs a held-out edit suite (default v2: 144 tasks derived from eight pinned, permissively licensed public repositories in Python, JavaScript, TypeScript, Go, Rust and C; v1: the original 10 authored tasks, now exploratory only) in `mars:hashline`, `mars:replace` and `mars:apply_patch` arms (the real `mars_edit` / `mars_replace` / `mars_apply_patch` runtime tools; formats plug in via `MARS_EDIT_FORMATS` + `MARS_EDIT_FORMAT_DRIVERS`) and an `omp-stock` arm (Oh My Pi built-in `read`/`edit`/`write`/`grep`, default model-resolved edit mode) under the same model, seed and per-task budget, and writes a sealed (sha256, optional HMAC) report, Markdown summary, trials and raw transcripts. The pre-registered bar (the MARS arm in the model's default edit format beats omp-stock with p < 0.05 on the paired exact sign test, cost per verified solve not worse; other MARS arms are secondary with Holm-adjusted p-values) is in `documentation/EVALUATION.md`, amended 2026-11-14 before any live run: an exact power analysis (`packages/evaluation/scripts/edit-bench-power.ts`) sets a 129-task minimum, and smaller suites run as exploratory with no verdict. `selectEditFormat` (`@mars/execution`) + `WorkbenchHostOptions.editFormats` / `mars serve --edit-format-evidence DIR` choose the per-model format from verified reports and record an `edit_format` task event with the report digest.

- Verified offline only: scripted fake models (`SCRIPTED_PROFILES`, zero real model calls) drive both arms end to end, including malformed patches, wrong whitespace, stale hashline anchors and ambiguous matches; both verdict directions are tested.
- **Honest limits**: the benchmark has **not** been run against any real model, so there is no evidence yet that MARS's harness beats omp for small models. v2 is powered (~80%) only for a large effect (MARS wins 70% of discordant tasks with 40% of tasks discordant); v2's code is public, so pretraining contamination of the surrounding code is certain (the instructed edits are new). Offline, `mars:apply_patch` cannot edit files over 50 KiB because Oh My Pi middle-truncates tool results over 50 KiB and patch sessions have no ranged `mars_read`. omp-stock's network isolation is in-process (`fetch` guard, no process-spawning tools), not OS-level; omp's own tools are not confined to the throwaway copy the way `mars_*` tools are. Delegated children use the static default format. Base-model pretraining contamination of the authored tasks cannot be ruled out.

## Decisions

- UI (from `documentation/UI_PROMPT.md`): every MARS client — interactive `mars session`, MARS Shell, VS Code — is a projection over `tasks.events`/`tasks.artifact`/`tasks.diff` and never a runtime; the terminal client is built from `@oh-my-pi/pi-tui` components and theme JSON (`src/theme/dark.json`, `light.json` are the token source of truth), with `@oh-my-pi/pi-coding-agent`/`pi-agent-core`/`pi-ai` imports forbidden in client code by lint. Usability conventions were taken from Codex CLI and Claude Code (approval card anatomy with `✔/✗` decision log, collapsed tool output with explicit expansion, footer hints by state, `Tab` queue vs `Enter` steer); visual language from Hermes and Oh My Pi. Where they conflict the document says which side won and why (§1.1). No `Full Access`/bypass mode and no LLM-as-approver exist in any client; paid models and screen capture are opt-in cards.
- MARS Shell window framework (ADR 0001, `documentation/adr/0001-shell-window-framework.md`): **Electron `44.10.2`** (current patch of the mature 44 line; 45 is the newest major and was not chosen).
